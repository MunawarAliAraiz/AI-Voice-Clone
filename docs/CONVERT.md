# Convert scripts and YouTube captions

## Current implementation — 2026-10-02

The Convert tab accepts pasted scripts or a YouTube video URL/ID. Users select
the source language explicitly: English, Hindi, or Urdu/Roman Urdu. A Latin
script is never treated as proof that the language is English or Urdu.

English and Hindi passages translate meaning into Urdu script or Roman Urdu.
Urdu passages retain the existing writing-system conversion prompts and
validators. `POST /api/text/transliterate` remains a durable queued job; its
optional `source_language` chooses the operation and is captured on the job.
Old clients and older rows without the field retain their existing conversion.
Gemma, its pinned weights, and the existing GPU scheduler remain the text runtime.
The desktop sends helper work to its managed Pod rather than loading local Torch.

Text preparation/caption import can run before model setup. GPU conversion has
the shared cloud readiness gate with a visible reason and setup/update action.
One conversion batch uses one model residency. A batch is limited to 200 parts;
the original captions/scripts stay visible beside editable converted drafts.
Sending prepared English/Hindi content to the Urdu editor requires converted
parts; partial batches send only usable converted/edited parts, in source order.
While a conversion runs, importing/replacing its source and starting another
part conversion are locked so results cannot be attached to a different script.

## Caption import

`POST /api/transcript/youtube` takes `url` and explicit `source_language`.
Only an existing English/Hindi/Urdu caption track is fetched. Manual tracks are
preferred over autogenerated captions in the same selected language; actual
track language and automatic-caption status are returned with the prepared text.
YouTube's automatic translation is not used. No video/audio, login cookies,
proxies, CAPTCHA solving or access bypass is implemented.

The local client uses `youtube-transcript-api==1.2.4`, declared in desktop build
requirements. The [upstream API](https://github.com/jdepoix/youtube-transcript-api)
supports track metadata and custom request sessions. Our session restricts
HTTPS requests to `www.youtube.com` watch/player/caption paths, disables redirects
and environment proxies, clears cookies, and refuses consent/access redirects.
Input IDs are exactly 11 allowed characters; accepted URL hosts are exact
YouTube/youtu.be names, with no credentials or unusual ports. Other hosts are
rejected before fetching.

Import limits: four requests, 4 MiB per response, 8 MiB total, 200,000 transcript
characters, five-second connection and ten-second individual read timeouts,
and a 40-second overall deadline checked between response chunks. A blocked
read can take up to its current read timeout to exit. Imported text is bounded
and never silently truncated. Missing captions, blocked access, oversized
responses and timeouts produce actionable failures with manual paste available.

## Verification and remaining qualification

- All 88 focused cases across conversion-language/caption, transcript API,
  transliteration API/validator and remote worker/helper suites passed. These
  cover URL/network bounds, language selection, manual track preference,
  blocked errors, queued translation metadata, echo rejection and old-worker
  compatibility refusal.
- The frontend production build and CSS variable check passed.
- One actual public English caption import returned a manual `en` track with
  2,089 characters in 1.69 seconds. Caption text was not printed or committed.
  This verifies that public caption fetching worked from this machine during
  that test; it does not guarantee every video/IP has accessible captions.

No live Gemma translation or listening test has been performed for the new
translation paths. Tests inject model outputs to verify lifecycle and contracts.
Script/length checks can reject malformed drafts but cannot establish semantic
accuracy; Roman Urdu cannot be distinguished from English by script alone.
Review every translated part before generation. Dialogue's Beta status and its
deferred listening tests are unchanged.
